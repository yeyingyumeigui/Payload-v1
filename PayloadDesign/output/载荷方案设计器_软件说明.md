## 一、软件概述

### 1.1 软件是什么

载荷方案设计器是一款**单机离线**的 Windows 桌面工具：用户输入一组任务需求（业务/轨道/覆盖/频段/体制），软件在数秒内完成从需求解析到方案评价的**全流程闭环设计**，输出可直接汇报的载荷方案（框图、链路预算、单机清单、平台/运载匹配、评级评分、Word 报告）。

### 1.2 解决什么问题

| 传统流程痛点 | 本软件的做法 |
|---|---|
| 指标拆解靠人工经验，口径不一 | 需求→EIRP/G/T 反推全公式化，与知识图谱判据 id 对齐、可追溯 |
| 链路预算用 Excel 手搭，易漏项 | 25 条工程约束（c-1~c-25）自动全检，雨衰/大气/指向/极化/实现损耗同源合成 |
| 天线/转发器/单机选型各自为政 | 五维天线选型 + 货架优先三线编号 + 平台/运载自动匹配，一条链贯通 |
| 方案可行性判断滞后 | 十项准则（6 硬 4 软）即时评级 A/B/C/D，不可行项直接给出修正建议 |
| 汇报材料重做 | 一键导出 Word 报告（含 11 张矢量图栅格化嵌入） |

### 1.3 技术架构

```
┌─────────────────────────────────────────────────┐
│  前端（WebView2 / Edge Chromium 渲染）             │
│  11 页签 SPA · SVG 交互图 · 三维覆盖 · 波束方向图    │
├─────────────────────────────────────────────────┤
│  pywebview JS 桥 ⇄ 本地 HTTP 双通道                │
├─────────────────────────────────────────────────┤
│  设计引擎 design_engine.py（五步闭环 + 双回环）      │
│  信息流引擎 infoflow_engine.py（c-1~c-25 校核）     │
│  GRASP 波束桥 grasp_bridge.py（偏置抛物面 PO）      │
│  协议生成 protocol_gen.py · 报告生成 report_gen.py  │
├─────────────────────────────────────────────────┤
│  知识库 design_data.py + 通信有效载荷知识图谱 JSON   │
│  （货架单机库/平台库/运载库/MODCOD 表/国家覆盖库）    │
└─────────────────────────────────────────────────┘
```

- **零外部服务依赖**：全部计算本地完成，断网可用；
- **单文件 exe**：PyInstaller 打包，双击运行（需系统已装 Edge WebView2 Runtime，Win11 自带）；
- **三种运行形态**：exe 桌面版（实时计算）、`python design_app.py --web` 网页版（实时计算）、预览版 HTML（8 场景预计算快照，任意浏览器打开）。

## 二、设计流程：五步闭环 + 双回环

### 2.1 五步闭环

| 步骤 | 引擎函数 | 做什么 | 关键输出 |
|---|---|---|---|
| ① 需求解析 | `parse_config` | 场景/业务/轨道/覆盖/频段 → 结构化需求 | 覆盖半径、容量需求 C_req、可用度→雨衰百分位 |
| ② 架构规划 | `derive_geometry` + `cfg_to_params` | 轨道几何推导（斜距/波束角/波束数）+ 体制映射 | θ_beam、N_geo、EIRP_req/GT_req 反推初值 |
| ③a 天线五维选型 | `select_antennas` | EIRP/G/T/重量/功耗/模式五维打分 + 频段硬过滤 | 货架天线或定制阵面参数 |
| ③b 转发器方案 | `plan_transponder` | EIRP 反推功放功率 + HPA 选型 + 信道化 | P_out、TWTA/SSPA/MPA 配置 |
| ④ 单机选型 | `build_equipment` | 货架优先三线编号（货架/继承/定制） | 单机清单（质量/功耗/成本） |
| ⑤ 链路校核 | `compute_all`（25 条约束） | 上下行预算、容量、频谱、平台承载全检 | M_up/M_dn/M_e2e、fail/warn 列表 |
| 平台/运载 | `select_platform` / `select_launcher` | 承载+供电可行域筛选 | 平台型号、整流罩包络 |
| 评价评分 | `evaluate_scheme` / `score_scheme` | 十项准则评级 + 六维加权评分 | A/B/C/D 级、0~10 分 |

### 2.2 双回环机制

- **内环（平台可行性换天线）**：初选方案质量/功耗超平台包络时，自动回退换更轻/更省电的天线方案，≤3 次迭代；
- **外环（链路余量否决重选型）**：链路校核发现余量不足且无法靠加功率解决时，携带排除清单重新选型，≤2 次；
- 回环全程留痕，在「⑩ 约束校验与回环」页签可见每次迭代的触发原因与结果。

### 2.3 一键建议值闭环

「💡 一键建议值」按钮对当前配置反推推荐参数（口径、阵元数、波束数、带宽、功放等），应用后自动重算并评级——`suggest_closed_loop` 验证其收敛性（自检中 1 次迭代即达 A 级、0 项需人工调整）。

## 四、快速上手

### 4.1 运行

| 形态 | 操作 | 适用 |
|---|---|---|
| **exe 桌面版**（推荐） | 双击 `tools\dist\载荷方案设计器.exe` | 日常设计，实时计算 |
| 网页版 | `python design_app.py --web` 后浏览器打开 | 开发调试 |
| 预览版 | 浏览器打开 `output\载荷方案设计器_预览版.html` | 无 Python 环境快速演示（8 场景预计算） |

> 运行要求：Windows 10/11 64 位 + Edge WebView2 Runtime（Win11 自带；如缺失，exe 会静默无法启动，请先安装 WebView2）。

### 4.2 标准操作流程（5 分钟出方案）

1. **选场景或填需求**：① 页签点任一内置场景载入，或手动选业务/轨道/覆盖/频段/体制；
2. **一键建议值**：点「💡 一键建议值」→「✓ 应用全部建议值」，补齐口径/阵元/波束/带宽等派生参数；
3. **开始设计**：点「🚀 开始设计」（含方案对比）或「⚡ 快速重算」（跳过对比）；
4. **看结论**：② 总览页查看评级——**A/B 可行，C 需优化，D 不可行**（按诊断建议修正后重算）；
5. **深查**：④⑤ 链路预算逐行核对，⑩ 约束页看 25 条判定与回环记录；
6. **导出**：「📄 导出 Word」生成汇报稿，或「🖨 打印 / PDF」。

### 5.1 验证方法：独立第一性原理交叉验证

### 5.3 验证发现并修复的真实物理缺陷（T_sys 相控阵噪声遗漏）

这是本次验证最重要的产出——**交叉验证抓出了一个此前所有测试都没发现的物理 bug**：

| 项目 | 修复前 | 修复后 |
|---|---|---|
| 缺陷机理 | 相控阵场景选用 `ant_rx_path` 接收链，但发布版知识图谱缺该节点 → 链为空 → T_sys = T_ant（仅 50~60K），**漏掉 T/R 组件首级 LNA 噪声** | `resolve_rx_chain` 检测空链/无首级放大器时合成默认链（相控阵→tr_module NF≈2dB；其他→lna+dconv），推导侧与校核侧同源 |
| LEO 宽带 G/T | 17.01 dB/K（**乐观约 6dB**） | **10.58 dB/K**（T_sys=219.6K，物理正确） |
| LEO D2D / IoT G/T | 8.22 dB/K | **2.39 dB/K**（T_sys=229.6K） |
| 影响评估 | 上行余量虚高，可能掩盖链路风险 | 修复后所有场景上行余量仍有 36~74dB（地面站强上行），结论不变但数值诚实 |

修复落点：`infoflow_engine.py`（新增 `resolve_rx_chain` + `compute_all` 调用）、`design_engine.py`（`_t_sys_family` 对齐同语义）。

## 六、关键工程口径速查

| 口径 | 取值/公式 | 说明 |
|---|---|---|
| FSPL | 20lg(d)+20lg(f)−147.55 | d 米、f 赫兹 |
| 雨衰缩放 | A(p,el)=A_ref·(p/0.01)^−0.6·sin30°/sin(el) | A_ref 为 0.01% 超越概率 30° 仰角参考值 |
| 指向损耗 | 12(θe/θ3dB)² | θe 指向误差 |
| 反射面增益上限 | G=η(πD/λ)²，η≤0.82 | P2 校验货架增益不超物理上限 |
| 相控阵增益 | 10lg(N_el·η)+G_el−cos^1.5(θ_scan) | 扫描损耗仅电扫阵 |
| 接收噪声 | T_sys=Friis 级联（KG 链或合成默认链） | 相控阵必含 tr_module（NF≈2dB） |
| G/T | G_ant−10lg(T_sys) | dB/K |
| EIRP | P_out+G_ant−L_feed−L_tx | L_tx 按 HPA 类型 3.5~4.7dB |

## 七、适用范围与限制

### 7.1 适用

- 通信卫星（GEO/MEO/LEO/SSO/HEO）有效载荷**方案论证与初步设计**；
- 业务类型：高通量宽带、广播电视、移动通信、手机直连 D2D、中继数传、军用抗干扰、窄带物联网；
- 频段：L/S/C/X/Ku/Ka/Q/V + 激光星间链路；
- 体制：透明/数字透明（DTP）/再生 × 固面/相控阵/伞状/大容量多波束/混合多波束。

### 7.2 限制（使用时须知）

1. **深度为方案级**：链路预算为典型值口径（雨衰用区域参考值而非 ITU-R P.618 逐站计算），不能替代详细设计阶段的逐链路精算；
2. **货架库时效性**：单机/平台/运载数据为知识库快照，工程引用前需与最新产品目录核对；
3. **GRASP 波束桥**：仅支持偏置抛物面（F/D=1.31）PO 计算，其他反射面类型自动降级 Airy 解析近似；
4. **覆盖示意图**：世界地图仅海岸线地理参考，**不含政治边界**，正式出版需换用合规审图底图；
5. **知识图谱依赖**：`ant_rx_path` 等接收链节点若缺失，引擎按合成默认链兜底（已在 P3b 验证不遗漏噪声），但建议保持 KG 与引擎版本配套；
6. **Ka/Q/V 雨衰**：高可用度（99.9%+）高纬度场景雨衰参考值可能偏保守，热带地区需实测修正。

## 九、常见问题

| 现象 | 原因与处置 |
|---|---|
| exe 双击无反应 | 缺 Edge WebView2 Runtime → 安装后重试（Win11 一般自带）；可查 `payload_designer_boot.log` |
| 评级 D | 看「⑩ 约束校验」页 fail 项：容量缺口→增波束/带宽；功率墙→换反射面或降 EIRP 需求；平台无解→减质量功耗 |
| 相控阵场景 G/T 与手算差 6dB | 手算若漏 T/R 组件 LNA 噪声会偏高——软件口径（含 tr_module NF≈2dB）为准 |
| 自定义参数不生效 | 预览版是快照，请用 exe 或 `--web` 版实时重算 |
| 导出 Word 打开格式异常 | 用 Microsoft Word（非 WPS 旧版）打开 .doc；打印/PDF 走浏览器内核更稳 |
