## 三、五大工作板块详述

### 3.1 智能体骨架与知识图谱（9/20）

**payload_agent 包**（零依赖可运行）：把载荷设计流程 Skill 化——

```
SK-INTENT（意图解析）→ SK-CLARIFY（缺项阻断闸）→ SK-RETRIEVE（知识图谱检索）
→ SK-ANTSEL / SK-EQUIP（天线与单机选型）→ SK-PLAT / SK-LAUNCH（平台与运载）
→ SK-BUDGET（链路预算）→ SK-VALID（质量闸）→ SK-DOC / SK-WORD（文档输出）
```

- **双回环**：内环 = 平台可行性换天线（≤3 迭代）；外环 = 链路余量否决天线重选型（≤2 次）
- **异常三级分级**：L1 自动降级 / L2 告警放行 / L3 中止转人工（30 条规则）
- **铁律**：禁止擅自假设、频段硬约束不回退、MODCOD 由 C/N 反推不预设体制
- 验证：`test_agent.py` **102 用例全过**，`demo.py` 8 用例走通

**通信有效载荷知识图谱 v3**（用户反馈驱动重构）：121 本体 / 167 属性 / 25 约束 / 129 关系；L0 载荷 → L1 五分系统（天线/转发器/激光/智能处理/公共基础）→ L2 分组（22 个）→ L3 体制(9)/单机(55)/链路(12)；链路/体制节点带 **chain 字段**（有序单机列表）自动派生关系边。配套交互式 HTML 查看器。

**附带产出**：PingCode 载荷设计流程 6 个月敏捷计划（274 工作项 / 365 故事点 / 8 CSV + HTML + MD）；载荷信息流仿真计算器（单文件 HTML 121.8KB，射频+激光+星内数据+系统校核）。

### 3.4 方案级稳健性分析（9/23，v5.3 核心）

新增 `analysis_engine.py` + `propagation.py`，实现 P0-P3 全 14 项改进：

- **蒙特卡洛链路灵敏度**：dB 域线性叠加（EIRP/G/T σ=0.5dB、雨衰对数正态、指向、极化、实现损耗），输出直方图 + 龙卷风图
- **可靠性三 R 口径**：r_serial（单串基线）/ r_asbuilt（按 BOM 标注）/ r_designed（标准 1:1 冗余）；series/pair/triple/k-out-of-n 全行型；MTBF_TABLE 分类保守值
- **冗余整改建议**（redundancy_advice）：二分反解 MTBF 提升倍数 + Π(1−q) 全量重算，GEO 实测 R 由 **0% → 75.05%**（8 加备 + 8 提 MTBF），未达 95% 诚实标注
- **邻星干扰 C/I**：ITU-R S.465-6 地面站旁瓣包络 + S.580/S.1428 卫星旁瓣，单/多入境
- **星蚀功率核算**：GEO 分点历元锚定（±400 天扫描）；**位保 ΔV/寿命**：齐奥尔科夫斯基（GEO 52 m/s/yr）
- **雨致交叉极化 XPD**：P.618-12 §4.1 全项（C_f/C_A/C_τ/C_θ/C_σ）
- **GRASP/SATSOFT/STK 结果回读**：4 类 RMS≈0 交叉校验
- 非 GEO 轨道（LEO/SSO/MEO/星座）正确降级

### 3.5 质量验证体系（贯穿全周）

**独立第一性原理验证** `_verify_physics.py`（~700 行）：不复用引擎函数，从教科书公式独立重写 **P0~P14 共 15 类物理量**交叉验证，10 个场景全部通过。

> **本周最大质量收获**：该验证体系**抓出一个真实物理 bug**——发布版知识图谱缺 `ant_rx_path` 节点 → 相控阵接收链为空 → T_sys 漏算 T/R 组件 LNA 噪声，G/T 乐观约 **6 dB**。修复后 leo_broadband GT 17.01→10.58 dB/K。教训：KG 数据缺节点会被静默兜底掩盖，任何"链为空就用环境值"的兜底都是物理隐患。

## 五、关键技术突破与踩坑

| 类别 | 问题 → 解决 |
|---|---|
| **Word 不渲染 SVG** | Word/WPS 的 HTML 导入滤镜只认 `<img>`，内嵌 `<svg>` 静默空白 → Edge headless `--screenshot` 把全部 SVG 光栅化为 PNG base64（1s/张，并行 4 路） |
| **exe 打开没反应** | pywebview 默认 coreclr 需单独装 .NET Desktop Runtime，缺失时 `import clr` 静默崩溃 → 强制 `PYTHONNET_RUNTIME=netfx`（Win10/11 自带 .NET Framework 4.8） |
| **JS 变量遮蔽** | 全局格式化函数 `n(v,nd)` 被局部 `const n` 遮蔽 → 波束面板整体降级；规约：单字母全局函数名禁止在函数体内复用 |
| **T_sys 物理 bug** | 见 3.5，KG 缺节点被静默兜底掩盖 → 独立验证抓出 |
| **可靠性整改误报** | redundancy_advice 只看 series 行，通道化大数组（72× TWTA）击穿容差时误报"无需加备" → 全行型闭环 + Π(1−q) 全量重算 |
| **并行 Edit 竞态** | 同一文件多处 Edit 同轮并行会互相覆盖丢改动 → 同文件多处修改必须串行 |
| **PowerShell 沙箱** | ConPTY ACCESS_DENIED(5) 可能持续复发 → 冻结 exe 验证改用 Python subprocess helper（CREATE_NO_WINDOW）绕开 |
| **中文路径 git** | `git diff --cached` 中文路径被引号转义致 shell 判断失效 → 用 Python 脚本 + `core.quotepath=off` 统计 |

## 七、航天工程启示

1. **「独立验证」是航天软件的刚需，不是可选项**。本周 _verify_physics 抓出的 T_sys 漏算（G/T 乐观 6dB）若流入方案，会导致链路余量虚高、整星可行性误判。航天型号「设计、验证、复核」三线分离的原则，在工具开发中同样成立——**用不复用源码的独立公式复算，才能发现源码级系统性偏差**。

2. **商业工具的「等效自研」要抓物理内核而非界面**。本周用纯 Python 复刻 GRASP/SATSOFT/STK 的核心算法（方向图、覆盖投影、轨道传播），证明在方案论证阶段，**抓住第一性原理（Friis、Hankel 变换、Kepler+J2）即可替代商业软件的大部分功能**，且零依赖、可冻结、可审计——这对自主可控有直接意义。

3. **稳健性分析把「可行」升级为「可靠」**。传统载荷设计止于链路预算闭合（可行），本周新增的蒙特卡洛灵敏度、可靠性三 R 口径、邻星干扰、星蚀/位保，把方案推到「在轨全寿命可靠」维度。**可靠性不是算出来的余量，而是设计出来的冗余**——redundancy_advice 从 0% 到 75% 的整改闭环正是这一思想的代码化。

4. **知识图谱 + 货架库 = 选型可追溯**。86 条对标真实产品（银河/SatNow/Tesat）的货架 + 121 本体图谱，使每个选型决策都能回溯到 level 编号、频段约束、物理判据，**杜绝「拍脑袋选型」**，这正是商业航天批产、供应链协同所需的数字化底座。
