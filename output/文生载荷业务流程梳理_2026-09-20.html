一、概述

一句话概括：文生有效载荷智能体把"一句自然语言需求"变成"一份可审计的卫星有效载荷方案"——通过 11 个 Skill 组成的确定性流水线（意图解析 → 澄清闸口 → 知识检索 → 三级选型 → 链路预算 → 三重校验 → 方案生成 → 文档导出），以货架产品库为知识底座，以双回环校核为质量闸门，以 L1/L2/L3 异常分级为处置机制。

1.1 业务背景

商业航天批产模式下，有效载荷方案设计存在三个痛点：

痛点传统模式表现智能体解法
设计周期长方案论证以周计，人工查手册、算链路、写文档全链路秒级生成，确定性公式可复现
知识分散货架产品信息散落在个人经验与纸质目录结构化货架库统一沉淀（天线/单机/平台/运载）
质量不一致校核项靠人工自觉，频段错配、余量不足时有发生三重校验闸门 + 30 条异常规则强制兜底

1.2 设计目标

1. 禁止擅自假设：需求缺项必须澄清，不得虚构用户约束（blocking 级缺项直接中断）。

2. 货架优先：飞行继承货架 > 飞行继承 > 货架(在研转货架) > 定制，缺口显式记录不回退。

3. 校核闭环：任何方案必须过"平台可行性 + 链路余量 + 三重校验"三道闸门，不通过即回环或转人工。

4. 确定性可审计：无 LLM 也能跑通全链路；每一步评分理由、计算过程全部留痕。

5. 异常分级处置：L1 自动降级不扰民、L2 告警放行等决策、L3 保护中止转人工。

3.1 SK-INTENT 意图解析

从自然语言提取结构化设计要素，关键词后端为主、LLM 后端可选增强（失败自动降级）。

提取要素说明陷阱规避
载荷类型通信/遥感/导航/科学，按关键词命中数取最优"遥感"与"通信数传"共现时按命中数裁决
轨道类型GEO/LEO/MEO/SSO/HEO未识别不默认，交澄清闸口
工作频段字母频段（Ka/Ku/L…）+ 数值频段数值必须带 GHz 上下文："12米伞天线""300kg""30万人"不得误判为频段；L 波段按特征频点（1525/1559/1626/1660 MHz）识别
关键技术相控阵/伞天线/DTP/激光通信/星上处理…—
转发体制transparent / regenerative / dtp透明转发与 DTP 共现 → 标记歧义

3.3 三级选型闭环

第一级：载荷方案（通信 = 天线 + 单机；非通信 = 载荷单机）

天线五要素评分（满分 100）：

要素权重判据不满足时
EIRP30能力 ≥ 需求按差距线性降分（每差 10 dB 扣光）
G/T25能力 ≥ 需求按差距线性降分（每差 8 dB 扣光）
重量20≤ 轨道参考包络按比例降分
功耗15≤ 轨道参考包络按比例降分
工作模式10单波束/多波束/波束跳变/在轨重构匹配不给分并记录冲突
货架水平+2heritage×0.5 加权同等条件优先飞行继承

频段硬过滤：有匹配频段产品时只返回匹配产品；全不匹配时降权 0.6 并标记。

单机货架组链（透明/DTP/再生三体制）：LNA → DCONV → OMUX → (DTP+MPA | SSPA/TWTA) → UCONV → CIRC，公用 SWITCH/BCN/TTC 恒配。频段硬约束：请求频段无货架品时记为定制缺口，绝不回退到错误频段产品（L 波段载荷配 Ka 变频器是工程错误）。

非通信载荷判据完全不同：遥感按分辨率 30/幅宽 20/数据率 15/质量 15/功耗 10/指向 10；导航按信号体制/EIRP·UERE/原子钟；科学按灵敏度/观测几何/数据率。

第二级：平台选型（五因子）

先做可行性预筛（轨道兼容 + 承载 ≥ 载荷质量 + 供电 ≥ 载荷功耗），再评分：轨道适配 15 + 承载贴合 30 + 供电贴合 25 + 寿命匹配 15 + 飞行成熟度 15。轨道包含关系：SSO 任务可由 LEO 平台承接（评分 12/15）。

第三级：运载选型（四因子）

入轨能力 40 + 经济性 25 + 飞行履历 20 + 整流罩包络 15；按轨道取对应能力列（GEO→GTO、SSO→SSO、LEO/MEO→LEO）；能力余量 >50% 提示搭载/拼单降本。

3.4 双回环校核机制

回环位置触发条件动作上限
内环（平台可行性）SelectionEngine.run载荷包络超所有同轨道平台能力换评分次序的下一候选天线重估3 次迭代
外环（链路余量）PayloadDesignChain三重校验不通过且失败项为链路余量否决当前天线型号（exclude），重跑选型2 次回环

回环耗尽仍不可行 → feasible=False（L3），方案文档给出"拆分多星 / 改换轨道 / 定制平台"人工决策建议。

3.5 SK-BUDGET 链路预算

计算链条（全部确定性公式，逐项留痕）：


FSPL = 20lg(d) + 20lg(f) − 147.55
C/N0 = EIRP − FSPL − (雨衰+指向+极化+大气+实现) + G/T − k(−228.6)
C/N  = C/N0 − 10lg(B)
余量 = C/N − 体制门限 ≥ 3 dB → 通过

关键设计：MODCOD 由 C/N 自适应反推（32APSK→16APSK→8PSK→QPSK DVBS2X 阶梯），即"先有链路质量，再定体制与容量"，而不是先锁高阶体制再看链路是否闭合。雨衰按频段基准值（0.01% 超越概率）做仰角修正（1/sin(el)）与可用性修正（p^-0.6）。星间激光链路固定 DPSK 体制不走自适应阶梯。测控/信标（S 波段）豁免业务频段校验。

3.7 SK-DOC 方案生成（十章结构）

一、需求分析 → 二、选型需求与判据（五要素表 + 来源标注）→ 三、载荷方案（体制/天线/单机/缺口 或 非通信载荷）→ 四、平台方案（含被筛除平台折叠表）→ 五、发射方案 → 六、指标汇总与平台校核 → 七、链路预算与余量校核 → 八、方案三重校验 → 九、风险与异常处置 → 十、结论。

9.3 与既有工作（Traework）的承接关系

本骨架承接 Traework 项目 2026-08-17~08-21 周的智能体设计成果：11 Skill 体系、异常分级规则表、三级选型闭环、五要素/五因子/四因子评分模型均对齐 skill_registry.py / selection_engine.py / payload_chain.py 的既有定义，并做了三项工程强化：① 频段硬约束（缺口显式化，不回退错误频段）；② MODCOD 由 C/N 自适应反推（修正预设体制导致余量为负的方向性错误）；③ 用户约束与工程参考包络分离（不虚构硬约束，可行性以平台实际能力为准）。
